# v0.1.1 Design

## Scope

v0.1.1 addresses two small usability issues from `ROADMAP.md`.

- Improve every numeric input so an initial `0` does not remain when the user starts entering a value.
- Allow the Settings tab to show the app state immediately after startup, even when no event has been registered.

This release does not add new domain features, persistence schema changes, sync, authentication, or broader PWA update flows.

## Current State

Numeric inputs are split across two implementations.

- `src/components/NumberField.tsx` is a reusable number field with stepper buttons.
- `src/pages/ManagementPage.tsx` defines a local `NumberInput` used by product price, bundle price, bundle component quantity, initial stock, reserved stock, and expense amount fields.

Both number inputs render a numeric `value` directly and parse changes with `Number(event.currentTarget.value)`. This makes empty input collapse back to `0`, which causes the visible `0` to remain during entry.

The Settings page already has an app state card and can display an "event not selected" subtitle, but `src/App.tsx` only renders `SettingsPage` when `effectiveSelectedEventId !== null`. With no events, tapping Settings changes the selected tab but leaves no Settings content visible.

## Numeric Input Design

Use `src/components/NumberField.tsx` as the single number input behavior for this release. It should remain a controlled component from the parent perspective: parents continue to pass a `number` value and receive `number` updates through `onChange`.

Internally, `NumberField` may keep a temporary string draft for the focused input.

Required behavior:

- When focused with value `0`, show an empty text field so the next typed digits replace the zero.
- Allow an empty string while the user is actively editing.
- When the user types a valid number, clamp it to `min` and `max` if those props are provided, then call `onChange` with the clamped number.
- On blur, normalize an empty or invalid draft to `min ?? 0`.
- Keep the stepper buttons working with the committed numeric value.
- Keep touch-friendly sizing and accessible labels.

`ManagementPage` should use this shared component for all current numeric inputs. The local `NumberInput` can either be removed or reduced to a small wrapper around `NumberField` if that keeps call sites simple.

## Settings Without Event Design

`App.tsx` should render `SettingsPage` whenever `screen === "settings"`, regardless of whether an event is selected. It should pass `eventId={effectiveSelectedEventId ?? undefined}`.

`SettingsPage` should treat `eventId` as optional.

- The app state card is always visible.
- CSV export buttons are disabled when there is no selected event.
- The dangerous reset action is disabled when there is no selected event.
- Labels that name the target event should show "イベント未選択" instead of a placeholder event id.
- No database reset or CSV export should run without a selected event.

This keeps the Settings tab useful as an app-level screen while preserving event-scoped exports and reset behavior.

## Data Flow

Numeric input remains local React state until each form is saved. Existing database writes continue to receive numbers.

Settings app state continues to come from `usePwaUpdate`. Event-scoped data such as sales, expenses, CSV exports, and reset actions should only use a concrete selected event id.

No Dexie schema or domain type changes are required.

## Error Handling

Invalid or empty numeric drafts normalize to `min ?? 0` on blur. This avoids saving `NaN` and keeps existing non-negative management fields stable.

Settings actions that require an event should be disabled without one. Defensive guards should also return early if called without a selected event id.

## Testing

Add or update focused tests:

- `NumberField` behavior: focusing a zero-valued field clears the visible zero, typing digits commits the intended number, and blur restores `0` or `min` when left empty.
- Management integration: at least one management numeric field accepts a new value from initial zero without producing a leading-zero entry.
- App navigation: with an empty database, tapping the Settings tab renders the Settings screen and the app state card.
- Settings page: CSV export and reset controls remain disabled when no event is selected.

Run the existing verification scripts when implementation is complete:

- `npm run test`
- `npm run lint`
- `npm run build`
