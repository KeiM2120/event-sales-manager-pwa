# v0.1.1 設計メモ

## 目的

`ROADMAP.md` の v0.1.1 では、現場での入力と起動直後の確認性に関わる小さな不便を解消する。

- 数値入力時に初期値の `0` が残り続ける挙動を改善する。
- アプリケーション起動直後にイベントが未設定でも、設定タブで「アプリ状態」を確認できるようにする。

この対応では、新しい業務機能、Dexie スキーマ変更、同期、認証、PWA 更新フロー全体の拡張は扱わない。

## 現状

数値入力は現在2系統に分かれている。

- `src/components/NumberField.tsx`
  - 共通部品として用意されているステッパー付き数値入力。
- `src/pages/ManagementPage.tsx` 内の `NumberInput`
  - 商品価格、セット価格、セット構成数量、初期在庫、取り置き数、経費金額で使われているローカル部品。

どちらも親から受け取った `number` をそのまま `value` に渡し、入力変更時に `Number(event.currentTarget.value)` で数値化している。そのため入力欄を空にした瞬間も `0` に戻りやすく、初期値 `0` の欄に金額や数量を入れるときに `0` が残って見える。

設定画面にはすでに「アプリ状態」カードがあり、イベント未選択時の表示文言も一部持っている。しかし `src/App.tsx` では `effectiveSelectedEventId !== null` のときだけ `SettingsPage` を描画しているため、イベントが1件もない起動直後は設定タブを押しても設定画面の中身が表示されない。

## 対象範囲

数値入力改善は、管理画面の数値入力すべてを対象にする。

- 商品価格
- セット価格
- セット構成数量
- 初期在庫
- 取り置き数
- 経費金額
- 既存または今後の `NumberField` 利用箇所

設定タブ改善は、イベント未登録またはイベント未選択の状態でも、設定画面のアプリ状態だけは確認できることを対象にする。CSV出力やイベント単位リセットは、引き続き選択イベントがあるときだけ実行可能にする。

## 数値入力設計

`src/components/NumberField.tsx` を v0.1.1 の共通数値入力として扱う。親コンポーネントから見たインターフェースはこれまで通り `number` の `value` と、`number` を受け取る `onChange` のままにする。

入力欄の内部では、フォーカス中だけ文字列の一時入力値を持つ。

必要な挙動は以下。

- `value` が `0` の状態でフォーカスされたら、入力欄の表示を空にする。
- 編集中は空文字を許容する。
- 数字が入力されたら、`min` と `max` が指定されている場合は範囲内に丸めたうえで `onChange` に数値を渡す。
- blur 時に空文字または不正な入力だった場合は `min ?? 0` に正規化する。
- `+` / `-` ボタンは、確定済みの数値を基準にこれまで通り動作する。
- 大きめのタップ領域とアクセシブルなラベルは維持する。

`ManagementPage` のローカル `NumberInput` は、共通 `NumberField` を使う薄いラッパーにするか、呼び出し側を直接 `NumberField` に置き換える。呼び出し箇所が読みやすい形を優先する。

## 設定タブ設計

`src/App.tsx` は、`screen === "settings"` であればイベント選択の有無に関係なく `SettingsPage` を描画する。

`SettingsPage` には次のように渡す。

```tsx
<SettingsPage database={database} eventId={effectiveSelectedEventId ?? undefined} />
```

`SettingsPage` 側では `eventId` を任意として扱う。

- 「アプリ状態」カードは常に表示する。
- 選択イベントがない場合、CSV出力ボタンは無効にする。
- 選択イベントがない場合、危険操作のリセットボタンは無効にする。
- 対象イベント名を表示する箇所では、イベントIDの代替表示ではなく「イベント未選択」を表示する。
- 選択イベントがない状態では、CSV出力やリセット処理を実行しない。

これにより、設定画面はアプリ全体の状態を確認する画面として常に使える。一方で、イベント単位の出力やリセットはこれまで通りイベントに紐づく操作として守る。

## データフロー

数値入力はフォーム内の React state として保持され、保存時に既存の database 書き込みへ渡される。親 state と保存データは引き続き `number` のままなので、ドメイン型や Dexie スキーマは変更しない。

設定画面のアプリ状態は、既存通り `usePwaUpdate` から取得する。売上、経費、CSV出力、リセットなどイベントに紐づく処理は、具体的なイベントIDがある場合にだけ対象データを絞り込む。

## エラー処理

数値入力の空欄や不正な一時入力は、blur 時に `min ?? 0` へ戻す。これにより `NaN` が親 state や保存処理へ流れ込まないようにする。

設定画面では、イベントが必要な操作をボタン無効化で防ぐ。ハンドラ側にも早期 return を残し、UI状態のずれが起きても CSV出力やリセットがイベント未選択で走らないようにする。

## テスト方針

以下を追加または更新する。

- `NumberField` のテスト
  - `0` の欄にフォーカスすると表示が空になること。
  - そのまま数字を入力すると意図した数値として `onChange` されること。
  - 空のまま blur すると `0` または `min` に戻ること。
- 管理画面の結合寄りテスト
  - 初期値 `0` の数値欄に入力しても、先頭に `0` が残る入力にならないこと。
- `App` のナビゲーションテスト
  - 空のDBで設定タブを押すと、設定画面と「アプリ状態」カードが表示されること。
- `SettingsPage` のテスト
  - イベント未選択時に CSV出力とリセット操作が無効であること。

実装完了時には以下を実行する。

```bash
npm run test
npm run lint
npm run build
```
